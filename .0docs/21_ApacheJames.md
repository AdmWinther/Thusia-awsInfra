# Apache James Mail Server

## Overview

Apache James is an open-source mail server used in this project to handle email sending and receiving. It is configured to run in a Docker container and is managed by Docker Compose.

## Configuration

The configuration for Apache James is generated by Terraform and provisioned to the EC2 instance. The key configuration files are:

### `james-database.properties`

This file configures the connection to the MariaDB database. It specifies the JDBC driver, database URL, username, and password.

```properties
database.driverClassName=org.mariadb.jdbc.Driver
database.url=jdbc:mariadb://db-container/james_db
database.username=james_user
database.password=james_password
```

### `mailetcontainer.xml`

This file defines the mail processing logic. It is configured to:
-   Relay all outgoing mail through AWS Simple Email Service (SES).
-   Store a copy of sent emails in the user's "Sent" folder.
-   Handle local delivery for recipients within the same domain.
-   Manage error handling and bouncing of emails.

### `smtpserver.xml`

This file configures the SMTP listeners. The server listens on three ports:
-   **Port 25**: Standard SMTP, with STARTTLS enabled.
-   **Port 465**: SMTPS (SMTP over SSL).
-   **Port 587**: Submission port for email clients, with STARTTLS enabled.

All listeners are configured to use a PKCS12 keystore for TLS.

### `imapserver.xml`

This file configures the IMAP listeners. The server listens on two ports:
-   **Port 143**: Standard IMAP, with STARTTLS enabled.
-   **Port 993**: IMAPS (IMAP over SSL).

Both listeners use the same keystore as the SMTP servers.

## Initialization

The Apache James server is initialized using the `james_initialize.sh` script. This script is executed when the EC2 instance is first created. It performs the following actions:
1.  Adds the domain `awin.dk` to the server.
2.  Creates a number of user accounts with predefined passwords.

## File Generation Modules

The configuration files for Apache James are generated by Terraform modules located in the `___ShredModules___` directory. The naming convention for these modules is `file_gen_james_xxx`, where `xxx` corresponds to the name of the generated file.

The following files are generated by their respective modules:
-   `james-database.properties`
-   `imapserver.xml`
-   `james_initialize.sh`
-   `mailetcontainer.xml`
-   `smtpserver.xml`

Once these files are generated, the main Terraform configuration file (`main.tf`) provisions them to the AWS EC2 instance during the server setup process.

## Docker Integration

Apache James runs in a Docker container named `james`. The container is defined in the `docker-compose.yml` file and is part of the same Docker network as the other services. This allows it to communicate with the MariaDB database container.

## Keystore Management for TLS/SSL

The Apache James server utilizes a Java Keystore for managing TLS/SSL certificates. This keystore is essential for enabling secure communication over SMTP and IMAP protocols.

### Keystore Creation Process

The keystore must be generated within the James Docker container to ensure compatibility with the Java Development Kit (JDK) environment used by the server. The general steps for creating and managing the keystore are as follows:

1.  **Run a temporary James container**: Start a standalone James Docker container to access its environment.
    ```bash
    docker run --rm --name james -it -d apache/james:jpa-3.6.1
    ```

2.  **Access the container's bash**:
    ```bash
    docker exec -it james bash
    ```

3.  **Generate the keystore**: Use the `keytool` utility to create a new keystore. When prompted, provide `james72laBalle` as the password. It is crucial to set the Common Name (CN) to the domain name used by the mail server (e.g., `mail.awin.dk`).
    ```bash
    keytool -genkey -alias james -keyalg RSA -keystore keystore
    ```

4.  **Transfer the keystore to local machine**: After generation, the keystore file must be copied out of the Docker container to your local machine. This file is required later when obtaining an HTTPS SSL certificate from an external issuer.
    ```bash
    docker cp james:/root/keystore /path/to/your/local/directory/keystore
    ```
    This will transfer the keystore to the Docker container host, if the container is running on you local machine, that is fine, but if you are running the container on an EC2, you now need to transfer the file from the EC2 to your local machine.
    You can use FTP to fetch the file. For FTP, you must first open FTP port of the EC2 via the security group and then use WinSCP to transfer the file.

### SSL Certificate Integration

After we get our SSL certificates using __SharedModules__/file_gen_SSL_Agent/ we need to integrate that with KeyStor we just made in the last step.
To use a trusted SSL certificate (e.g., from Let's Encrypt or ZeroSSL), the following steps are involved after generating the keystore:

1.  **Generate a Certificate Signing Request (CSR)**:
    ```bash
    keytool -certreq -keyalg RSA -alias james -file certreq.csr -keystore keystore
    ```
    The `certreq.csr` file will contain the request to obtain an SSL certificate from a Certificate Authority (CA).

2.  **Obtain SSL Certificates**: Submit the CSR to a CA (e.g., ZeroSSL). The CA will provide certificate files, typically including a server certificate (e.g., `certificate.crt`) and a CA bundle (e.g., `ca_bundle.crt`).

3.  **Import Certificates into Keystore**:
    *   Import the CA bundle first:
        ```bash
        keytool -import -alias root -keystore keystore -trustcacerts -file ca_bundle.crt
        ```
    *   Then, import the server certificate:
        ```bash
        keytool -import -alias james -keystore keystore -trustcacerts -file certificate.crt
        ```

After these steps, the keystore will contain the necessary certificates for secure TLS/SSL communication. The `keystore` file is then provisioned to the James container during the Terraform deployment.
